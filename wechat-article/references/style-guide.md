# 公众号文章写作风格指南

> 基于：花叔自媒体增长数据分析（2026.03）
> 方法论：费曼学习法（说人话）+ 金字塔原理（结论先行）+ HKR 内容模型
> 更新时间：2026-05-27（新增手机端可读性黄金规则）

---

## 核心原则

### 0. 每篇文章必须同时提供两种价值（2026-07-28 新增）

> 背景：历史数据表明，文章表现差距可达180倍（9阅 vs 3987阅）。差距不在"写得好不好"，在"有没有给读者价值"。

| 价值类型 | 定义 | 检验标准 | 决定什么 |
|----------|------|----------|----------|
| **实用价值** | 读者看完能拿走的东西 | 有可复用的框架/清单/数据/判断吗？ | 读者**会不会收藏** |
| **情绪价值** | 读者看完产生的感受 | 有没有被戳中/激励/吓到/想反驳？ | 读者**会不会转发** |

**铁律**：两个都没有，就没有然后。

**历史数据验证**：
- 两个都有（菲尔兹奖1632阅、房产红利3987阅、npm供应链2178阅）→ 爆文
- 只有实用（程序员提效9阅）→ 死
- 只有情绪（Claude9秒删公司57阅）→ 留不住人

**传播力预估 = 实用(1-10) × 情绪(1-10)**。乘积 ≥49 才有爆文基础。

> 自媒体的核心判断：读者花时间看你的文章，本质是一笔交易——用几分钟生命换你给的东西。既没教他什么，也没让他感受到什么，这笔交易就是亏的。亏一次，他下次就不点开了。

### 1. 教程型内容是涨粉主力

教程型内容的涨粉效率是流量型内容的 127 倍。

| 内容类型 | 涨粉效率 | 互动率 |
|----------|----------|--------|
| 教程型 | 高（280‱） | 15%+ |
| 热点解读 | 中（65‱） | 5% |
| 流量型 | 低（2.2‱） | <1% |

**结论：写教程，不写资讯。**

> ⚠️ 2026-05 数据修正：纯方法论/教程类实际表现最差（45阅、9阅），而"深度洞察+个人实测"类表现最好（1632阅）。教程型内容要包装成"个人实测+深度洞察"，杜绝纯工具教程。

### 2. 标题决定 50% 阅读量

**标题公式**（按效果排序）：

| 公式 | 示例 | 效果 |
|------|------|------|
| 权威锚点 + 反常识判断 | "所有人都觉得没必要改的东西，他们改了" | 均阅读 8.1 万 |
| 个人实践 + 可量化结果 | "我用 AI 做了个付费榜第一的 App" | 均阅读 4.1 万 |
| 稀缺限定 + 大叙事 | "被收购前最后一次访谈" | 高打开率 |

**最大错误**：纯信息型标题（如"从 GLM-4.5 到 GLM-5"）

> ⚠️ 2026-05 数据验证：标题必须包含具体人物/事件/数字。1632阅的标题有"菲尔兹奖得主"，497阅的有"房产红利"，9阅的没有任何锚点。

**反例 → 正例**：
- ❌ "OpenClaw 技能库实战：给 AI 装上专业大脑"
- ✅ "我用 339 个免费技能，把 AI 调教成了 24 小时助手"

### 3. 金字塔原理：结论先行

**四个原则**：

| 原则 | 应用 |
|------|------|
| 结论先行 | 开头第一句就是钩子，不要铺垫半天 |
| 以上统下 | 每段第一句是中心句，后面支撑它 |
| 归类分组 | 相关内容放一起，不东一榔头西一棒子 |
| 逻辑递进 | 按重要性排列，先说最重要的 |

> ❌ 我最近在研究 AI，试了很多工具，发现有个叫 OpenClaw 的挺好用...
>
> ✅ OpenClaw 让我一天产出 5 篇公众号文章。之前这个量需要一周。

### 4. 费曼学习法：说人话

**写作时问自己**：
- 这个术语后面有没有"说人话"解释？
- 能不能用比喻代替专业描述？
- 想象一个 10 岁小孩，他会在哪里卡住？

**教是最好的学**：写教程型内容，既涨粉，又倒逼自己真正理解。

### 5. HKR 内容质量模型

| 维度 | 含义 | 检验标准 |
|------|------|----------|
| **H = Happiness** | 快乐感、好看、有趣 | 读者愿意看完吗？ |
| **K = Knowledge** | 知识增量、信息密度 | 读者能学到东西吗？ |
| **R = Resonance** | 共鸣、情绪连接 | 读者会有"这就是我想说的"感觉吗？ |

**自检**：
- 只有 H → 娱乐向，没深度
- 只有 K → 干货向，没感情
- 只有 R → 情绪向，没价值
- **H+K+R = 好内容**

### 6. 比喻不只是解释工具，更是表达武器

AI 写作的常见问题是"逻辑正确但情感缺席"。

**描述 vs 感受**：
> ❌ "它写出来的中文有一种很难形容的翻译腔"
>
> ✅ "那种扑面而来的翻译腔，简直浓得化不开"

**参数 vs 性格**：
> ❌ "本地模型快但偶尔犯错，云端模型贵但质量好"
>
> ✅ "本地模型是严谨话少的数字保险箱，云端模型是懂中国人心思的智囊大脑"

**原则：读者记住的是性格和画面，不是参数和结论。**

## 格式规范

### 允许的格式

| 格式 | 用途 | 效果 |
|------|------|------|
| **局部加粗** | 只加粗关键词（非整句），制造扫读锚点 | ✅ 强烈推荐 |
| 段落空行 | 分隔内容块 | ✅ 推荐 |
| `> 引用` | 金句、核心结论、原话、AI指令——跟正文区分开 | ✅ 强烈推荐 |
| `` `行内代码` `` | 工具名（`Claude Code`）、技术术语、指令文本 | ✅ 推荐 |
| 表格 | 信息密集区 | ✅ 保留 |
| `---` | 分隔大章节 | ✅ 全文 ≤ 3 处 |
| `###` 小标题 | 分隔内容块 | ✅ 推荐 |
| `##` 章节标题 | 文章主要分段 | ✅ 推荐（用 ## 而非 ###） |
| `<!-- IMAGE:chartN -->` | 配图占位符，放在正文对应位置 | ✅ 初稿阶段必须插入 |

### 禁止的格式

| 格式 | 原因 |
|------|------|
| 有序列表 `1. 2. 3.` | ❌ 像技术文档，有距离感 |
| 无序列表 `-` 或 `*` | ❌ 同上 |
| 多行代码块 | ❌ 公众号不支持 |
| **整句加粗** | ❌ 扫读时没有锚点感，改成只加粗关键词 |

### 可读性加分规则

1. **局部加粗而非整句加粗**："你**毁掉信任**只需要一个 bug，**重建信任**可能需要一个月" 比 "**你毁掉信任只需要一个 bug，重建信任可能需要一个月**" 更有冲击力
2. **引用块用于三层内容**：① 金句/核心结论 ② 他人原话 ③ AI 指令/命令，让这些内容跟正文视觉分离
3. **行内代码包裹工具名和指令**：`Claude Code`、`Codex`、`Cursor Bugbot`、"找出所有可能的 bug"，Raphael 会渲染成淡灰底色，技术感更强
4. **分隔线控制节奏**：大章节之间用 `---`，但全文不超过 3 处，太多反而打断阅读流
5. **配图占位符紧跟相关段落**：`<!-- IMAGE:chart1 -->` 必须在写初稿时就插入，不要写完再补

### 列表转换规则

- 3 个以下要点 → 自然段落串联
- 4-6 个要点 → 编号列表或合并为段落
- 7+ 个要点 → 保留列表但加总结
- 功能介绍 → 用表格更直观

### 转换示例

❌ 列表写法：
```
- 支持多种格式
- 自动排版
- 一键导出
```

✅ 自然段落写法：
```
它**支持多种格式**，不管是 Markdown 还是 Word 都能处理。排版也是**全自动的**，一键就能**导出**到公众号后台。
```

## 手机端可读性黄金规则（2026-05-27 新增）

> 背景：公众号 90%+ 阅读在手机端。手机屏幕一行约 20 个中文字，视觉密度极高。
> 之前文章的问题是段落太长太密，缺乏节奏变化，读起来像论文不像聊天。

### 规则 1：3 行法则

每个段落**不超过 3 行**（约 60 个中文字）。超过就拆。

拆分方式：短结论独占一行，展开解释放在下面。

**示例**：

❌ 太密：
```
他花了几个月，把这套流程全扔了。LibreOffice 替代 Word。LaTeX 替代 InDesign。Python 脚本自动转格式。Git 追踪每次修改。改一个错别字，git commit 一次，脚本跑一遍，PDF 和电子书同步更新。
```

✅ 拆开后：
```
他花了几个月，把这套流程**全扔了**。

LibreOffice 替代 Word。LaTeX 替代 InDesign。Python 脚本自动转格式。Git 追踪每次修改。

改一个错别字？**git commit 一次，脚本跑一遍，PDF 和电子书同步更新。**
```

### 规则 2：每 3 段必有一个视觉锚点

连续 3 个普通段落后，必须插入一个**视觉锚点**——三选一：

1. **加粗关键词**（不是整句，只加最炸的那几个字）
2. **引用块金句**（`> xxx`）
3. **超短句独占一行**（10 字以内，像一个鼓点）

让读者扫读时眼睛有地方停。

**锚点密度自检**：用拇指快速往下划，如果划了 3 屏还没看到一个加粗/引用/短句，说明太密了。

### 规则 3：长短交替节奏

长段落（2-3 行）之后跟一个短句（1 行，甚至几个字）。

不能连续 3 个以上长段落。读者会喘不过气。

**节奏模板**：
```
[长段 2-3行：讲一个场景或观点]

[短句 1行：结论或情绪]

[长段 2-3行：展开或举例]

> [引用块：金句总结]

[短句]

[长段]
```

### 规则 4：一段一观点

每段只讲**一件事**。如果一段里出现「但是/然后/另外/还有」，大概率该拆段了。

自检：读一遍这个段落，用一句话概括。如果概括不了，说明塞了太多东西。

### 规则 5：引用块节奏

至少每 **300 字**出现一个引用块（`> xxx`）。

引用块的三种用法（让眼睛有停靠点）：
1. **金句总结** — 一段论述后，用引用块提炼核心观点
2. **原话引用** — 引用别人的话，跟正文视觉区分
3. **反问/痛点** — 「这不是创作，这是在工具之间当搬运工。」

### 规则 6：避免信息堆积段

连续出现 2 个以上工具名/数字/专有名词的段落，必须拆成三步走：

1. **先说结论**（这东西解决什么问题）
2. **再举例**（具体工具/数字）
3. **最后总结**（一句话收回来）

**示例**：

❌ 信息堆积：
```
DeepSeek 有个前缀缓存机制，命中率 99.82%，4.35 亿 token 只花了 12 美元，不做缓存要 61 美元，差 5 倍。
```

✅ 三步走：
```
有个机制能让 API 费用直接**砍掉 80%**。

它叫前缀缓存。原理很简单：发给 API 的内容，前面跟上次一模一样，前面这部分走缓存价，打一折。有人靠这个，4.35 亿 token 只花了 12 美元。

> 不做缓存优化，同样工作量要花 61 美元。一天差 5 倍。
```

## 互动埋点规则（2026-06-15 新增）

> 数据诊断：几百阅读但点赞率0.3-0.9%、评论几乎为0。核心问题是内容缺少"让人想说点什么"的触发点。

每篇文章**必须**包含至少3个互动触发器：

### 触发器 1：文中提问（放在文章中段）

抛一个读者一定会想回答的问题。问题要**具体、有利益相关、低门槛**。

**好问题示例**：
- "你现在每月花多少在AI工具上？"
- "你团队里第一个被AI替代的会是谁？"
- "你试过用AI写代码吗？最抓狂的是哪一次？"

**烂问题示例**（不要写）：
- "你怎么看？"（太空泛）
- "欢迎评论区聊聊"（没有具体方向）

### 触发器 2：争议观点（放在文章前1/3处）

故意说一句有人会不同意的话。争议 = 评论。

**示例**：
- "说实话，90%的程序员学了AI之后，效率没提高，反而降低了。"
- "我觉得未来3年内，独立开发者比大厂程序员更安全。"

然后后面用数据/案例去论证它。不需要偏激，但要有明确立场。

### 触发器 3：金句截图位（放在文末）

专门设计一句适合截图发朋友圈的话，15字以内，用引用块标记。

**示例**：
> AI不会取代你，但会用AI的人会。
> 
> 不是你不够努力，是你努力的方向变了。

**自检**：这句话单独拿出来，没有上下文，读者还想截图转发吗？

## 文章结构模板

### 开头（150 字以内）

**必须包含**：个人实践 + 量化结果（钩子）+ 痛点共鸣

**模板**：
```
上周我用 [工具/方法]，[量化结果]。之前这个量需要 [对比时间]。

你是不是也有过这种经历：[痛点描述]...
```

**示例**：
> 上周我用 OpenClaw 技能库，一天产出了 5 篇公众号文章。之前这个量需要一周。
>
> 你是不是也有过这种经历：做自媒体的时候，想追热点但不知道今天写什么...

### 主体

**每个场景/段落的结构**：
1. 场景标题（一句话痛点）
2. 解决方案（1-2 段自然语言）
3. 实测效果（数据）
4. 使用示例（对话/操作流程）

**避免**：
- 过多的 `---` 分隔线（全文 ≤ 3 处）
- 过多的列表（改用自然段落）
- 过多的截图标记（只在关键处标注）

### 结尾（100-150 字）

**当前阶段策略（变现模式未跑通前）**：

不引流加好友，避免引入白嫖用户。用「关注 + 转发 + 在看 + 评论」提升账号权重和传播。

**结尾结构（当前阶段，2026-06-15 升级）**：

1. **一句真诚的感谢**（像《头号玩家》里 Halliday 对 Parzival 说的 "Thank you for playing my game"）——简短、真诚、有点温度，没有多余的话。让读者感觉到你是写给他的，不是写给所有人的。
2. **互动钩子**：一个具体的、跟文章内容相关的问题，诱导评论（必须有具体方向，不能是空泛的"你怎么看"）
3. **关注理由**：给一个**具体的**下一个内容的期待，不是"每天分享AI实战"，而是"关注我，明天拆解xxx"
4. **转发引导**：具体的转发场景，不是"转发给朋友"，而是"转发给你那个还在纠结xxx的朋友"

**模板（当前阶段首选）**：
```
[一句跟文章内容相关的真诚感谢，2-3句话]

[一个具体的问题，跟文章内容直接相关，读者一定会想回答]

点个**关注**，[具体的下一个内容预告/系列化承诺]。

觉得有用的话，帮忙**转发**给[具体场景的人]，这对我是最大的支持。
```

**互动钩子示例**（每篇不同）：
- "你现在每月在AI工具上花多少钱？评论区对个账。"
- "你觉得你的工作，AI能替代百分之多少？"
- "你第一次用AI写代码是什么感觉？我先说：像个不会沟通的同事。"

**关注理由示例**（要具体，不要泛泛）：
- "这是AI日报第N期，关注了就不会错过明天的。"
- "明天我会拆解xxx的实际成本，关注了到时候直接抄作业。"
- "这个系列我会一直写下去，关注了相当于定了个免费的AI内参。"

**感谢句示例**（每篇不同，不要重复）：
- "谢谢你看到这里。我知道一个人做这些事不容易，能有人愿意读完我写的东西，这本身就很让我开心。"
- "每次写完一篇文章，我都会想：会不会有人因为这个少走点弯路？如果你是那个人，那这半小时就值了。"
- "一个人干最大的问题就是没人交流。你愿意花时间看我的文字，对我来说就是最好的鼓励。"

**变现跑通后切换为**：加好友引流（沉淀私域），提供具体诱饵（文档/工具包/课程试听）。

**CTA 模板（变现跑通后启用）**：

**模板 A：加好友引流**
```
[一句话总结价值]

这套 [产品/方法] 我整理成了一份完整文档。

扫码加我微信，备注"[暗号]"，我发你。
```

**模板 B：加群引流**
```
[一句话总结价值]

想体验 [具体效果]？

扫码进群，群公告里有 [资源链接]。
```

**结尾原则**：
- 必须给读者一个具体动作
- 不要只说"评论区聊聊"——那是浪费流量
- 当前阶段：关注 + 转发为主，先做大账号权重

## 产品/工具提及规范

如果文章涉及产品（如 OpenClaw），**必须有一句话定义**：

> "OpenClaw 是一个 AI 助手框架，可以理解为一个能帮你干活的智能管家。"

如果涉及"快速生成"（如 AI 写作），**必须加打消顾虑说明**：

> "虽然是 X 分钟生成的初稿，但因为输入了高质量的指令和风格指南，初稿的可读性已经超过了 80% 的新手作者。人工微调是为了注入灵魂，而不是修改错别字。"

## 检查清单

写完文章后逐项检查：

### 标题
- [ ] 包含量化数据？
- [ ] 有反常识判断或个人实践？
- [ ] 避免了纯信息型描述？

### 开头

## 快速优化指南

### 如果文章像技术文档

**信号**：大量列表、功能罗列、缺少个人语气

**解法**：
1. 列表改加粗关键词 + 自然段落
2. 步骤用 `### 第一步` 小标题
3. 加入"我"的视角和体验
4. 用对话示例代替功能说明

### 如果小标题层级不对

**信号**：用了 `###` 作为文章主要分段标题

**解法**：文章主要分段统一用 `##`（二级标题），不要用 `###`（三级标题）。`###` 只在极少数需要子分段时使用。

### 如果标题不够吸引

**信号**：纯描述性、没数字、没悬念

**解法**：
1. 加入量化数据（"我用 X 做了 Y"）
2. 加入反常识判断（"所有人都觉得...但其实"）
3. 加入稀缺性（"第一次公开"）
