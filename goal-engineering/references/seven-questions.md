# 七问详解 + 示例

> 每次 delegate_task 前过一遍。执行型至少填 1/2/4，探索型至少填 1/2/3/7。

---

## 七问详解

### 1. Why — 目的

这个活为什么干？干完什么样？

**判断标准**：一句话能说清。如果说不清，说明你自己还没想好，子 agent 更不可能想好。

**反面案例**："优化一下网站" — 为什么优化？优化什么？优化到什么程度？

**正面案例**："首页加载速度从 3s 降到 1s 以内，因为移动端跳出率和加载时间强相关"

### 2. Done — 完成态

具体到什么程度算完？

**判断标准**：船靠岸那一刻就能判断，不需要额外讨论。

**反面案例**："把关键词调研做了" — 做了多少个？什么格式？什么深度？

**正面案例**："交付 5 个关键词，每个附月搜索量、竞争度、SERP 前 10 名 URL，写入 keywords.md"

### 3. Proof — 证据

谁验？怎么验？子 agent 回传什么？

**判断标准**：验收者不需要重新做一遍，只看证据就能判定。

**反面案例**："调研完了，结论是 xxx" — 没有来源，无法验证

**正面案例**："每个关键词附 Google 搜索结果 URL + 截图，搜索量附工具名称和查询日期"

### 4. Anti — 反作弊

最偷懒的达标方式是什么？怎么堵死？

**判断标准**：想想"如果我是子 agent，我怎么用最少力气糊弄过去"。

**反面案例**：goal 写"部署网站" → 子 agent 部署了一个空白页就说过关了

**正面案例**：goal 写"部署网站" + 防偷懒："必须回传可访问的 URL，URL 打开必须看到首页内容，不能是 404 或空白页"

### 5. Bounds — 边界

只能改哪些路径？预算多少？

**判断标准**：白名单 + 黑名单 + 预算上限，三件套。

**反面案例**："重构代码" → 子 agent 把整个项目改了一遍

**正面案例**："只允许改 src/analysis/，禁止改 src/routes/ 和数据库 schema，30 分钟内完成"

### 6. Trade — 取舍

冲突时保哪个？

**判断标准**：写明优先级顺序，子 agent 遇到冲突时不用猜。

**反面案例**：没写取舍 → 子 agent 遇到"改了性能但测试挂了"时不知道该回退还是继续

**正面案例**："正确性 > 完整性 > 速度 — 测试挂了就回退，宁可少做不可做错"

### 7. Unknown — 未知

摸不准的怎么办？

**判断标准**：写下来跳过继续，不硬闯不停。

**反面案例**：子 agent 遇到不认识的报错，卡住 10 分钟反复重试

**正面案例**：goal 里写"遇到无法解决的问题写进返回结果，跳过继续，不硬闯不停"

## 做站线七问示例

### 场景：delegate 关键词调研

| # | 填写 |
|---|------|
| 1 Why | 找出 og-image generator 的 5 个高价值目标关键词，用于 SEO 内容规划 |
| 2 Done | 5 个关键词写入 keywords.md，每个附搜索量、竞争度、SERP 前 10 |
| 3 Proof | 每个关键词附 Google 搜索 URL + 截图，搜索量附工具名 + 日期 |
| 4 Anti | 编造数据 = 失败；只给热门词不评估竞争 = 失败 |
| 5 Bounds | 最多查 15 个来源，20 分钟 |
| 6 Trade | 精准 > 数量 — 宁收 2 条实的，不收 10 条凑的 |
| 7 Unknown | 搜索量太低的标注"小众但精准"跳过，不硬挖 |

### 场景：delegate 前端部署

| # | 填写 |
|---|------|
| 1 Why | 把 og-image-generator 部署到 Vercel，确保线上可访问 |
| 2 Done | URL 返回 200，移动端无横向滚动 |
| 3 Proof | curl 返回 200 + 移动端截图 + commit_sha |
| 4 Anti | 只改代码不部署 = 失败；部署旧版本 = 失败 |
| 5 Bounds | 只改 src/、public/、vercel.json，15 分钟 |
| 6 Trade | 能访问 > 样式完美 > 加载速度 |
| 7 Unknown | Vercel 配置冲突写进返回结果，跳过 |

### 场景：delegate 竞品定价分析

| # | 填写 |
|---|------|
| 1 Why | 分析 3 个竞品的定价策略，给出我们的定价建议 |
| 2 Done | 3 条竞品定价 + 1 条定价建议，写入 pricing-analysis.md |
| 3 Proof | 每条附竞品定价页 URL + 截图 + 访问日期 |
| 4 Anti | 编造定价 = 失败；只列竞品不给建议 = 失败 |
| 5 Bounds | 最多查 10 个来源，15 分钟 |
| 6 Trade | 有数据 > 有建议 — 没有实测定价就不给建议 |
| 7 Unknown | 竞品无公开定价 → 标注"需询价"跳过 |
