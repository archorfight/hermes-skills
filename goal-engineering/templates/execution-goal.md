# 执行型 Goal 模板

> 适用于：代码开发、部署上线、内容产物、配置变更
> 核心原则：验收条件 = 可执行命令或可检查文件，防偷懒条款写明基线不可退

---

## 模板

```
## 目标
[一句话意图 + 干完什么样]

## 验收
- [命令或文件路径]：[判定标准]
- [命令或文件路径]：[判定标准]
- 证据回传：[具体内容，如 commit_sha、URL、文件路径]

## 防偷懒
- 最可能的偷懒方式：[描述] → 堵死条件：[描述]
- 基线不可退：[当前基线数字，如测试数/覆盖率/性能指标]

## 边界
- 只允许改：[白名单路径]
- 禁止改：[黑名单路径]
- 预算：[时间上限 / 调用次数上限]

## 取舍
- 冲突时优先级：[如 "正确性 > 完整性 > 速度"]

## 未知
- 摸不准的写进返回结果，跳过继续，不硬闯不停
```

---

## 示例：前端部署

```
## 目标
把 og-image-generator 部署到 Vercel，确保线上可访问。

## 验收
- `curl -sI https://og-image-generator.vercel.app` 返回 200
- 移动端截图：375px 宽度下首页无横向滚动
- 证据回传：部署 URL + commit_sha

## 防偷懒
- 只改前端代码不部署 → 堵死：必须回传可访问的 URL
- 部署旧版本凑数 → 堵死：commit_sha 必须是最新 commit
- 基线不可退：现有页面加载时间 < 2s，部署后不得劣化

## 边界
- 只允许改：src/、public/、vercel.json
- 禁止改：package.json 依赖版本
- 预算：15 分钟内完成

## 取舍
- 能访问 > 样式完美 > 加载速度

## 未知
- Vercel 配置冲突写进返回结果，跳过继续
```

## 示例：代码重构

```
## 目标
重构 banana-pro 的关键词分析模块，把同步调用改为异步，提升响应速度。

## 验收
- `npm test` 全部通过
- 测试覆盖率 >= 当前基线（82%）
- 响应时间 P50 < 500ms（当前 1.2s）
- 证据回传：commit_sha + 测试报告路径

## 防偷懒
- 删测试降低标准 → 堵死：覆盖率不得下降
- 只改简单函数凑数 → 堵死：必须包含核心分析函数
- 基线不可退：测试数 47 个，不得减少

## 边界
- 只允许改：src/analysis/、src/utils/
- 禁止改：src/routes/、数据库 schema
- 预算：30 分钟

## 取舍
- 正确性 > 性能 > 代码风格

## 未知
- 遇到无法异步化的函数写进返回结果，跳过
```
