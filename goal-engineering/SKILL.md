# Goal Engineering

> **结论先行**：每次 `delegate_task` 前，过七问自检、选模板、写 goal。结果回传后，跑明卷+暗卷验收。

## 什么时候加载

- 准备 `delegate_task` 派活时
- 用户说"帮我派活"/"帮我 delegate"/"写个 goal"
- 用户说"验收一下"子 agent 的返回结果
- 用户说"子 agent 又偷懒了"/"delegate 质量不行"

---

## 一、派活前七问自检

每次 delegate 前过一遍。**不需要全填**——执行型至少填 1/2/4，探索型至少填 1/2/3/7。

| # | 问题 | 判断标准 | 执行型必填 | 探索型必填 |
|---|------|----------|:---:|:---:|
| 1 | **Why** | 一句话说清这个活为什么干、干完什么样 | ✓ | ✓ |
| 2 | **Done** | 具体到什么程度算完？命令跑过？文件存在？结论条数达标？ | ✓ | ✓ |
| 3 | **Proof** | 谁验？子 agent 回传什么证据？URL？commit_sha？文件路径？ | ✓ | ✓ |
| 4 | **Anti** | 最偷懒的达标方式是什么？怎么堵死？ | ✓ | — |
| 5 | **Bounds** | 只能改哪些路径？预算多少（时间/调用次数）？ | — | — |
| 6 | **Trade** | 冲突时保哪个？（算得对 > 做得全 > 做得快） | — | — |
| 7 | **Unknown** | 摸不准的怎么办？写下来跳过，不硬闯不停 | — | ✓ |

### 七问填写示例

**做站线（执行型）**——delegate frontend-site-automation 部署前端：

> 1. **Why**：PRD 设计真源要落地成可访问的前端页面
> 2. **Done**：部署 URL 可访问 + 移动端截图正确
> 3. **Proof**：回传部署 URL + curl 200 + 移动端 viewport 截图
> 4. **Anti**：最偷懒 = 只部署桌面端没做移动端适配 → 堵死条件：必须贴移动端截图

**公众号线（探索型）**——delegate 知识库搜索给选题建议：

> 1. **Why**：从已有素材中找到值得写的选题方向
> 2. **Done**：3-5 个选题，每个附素材来源 + 预估热度
> 3. **Proof**：每个选题必须附 kb_search 的原始素材 ID + 来源 URL
> 7. **Unknown**：知识库覆盖不到的方向，标注 [missing]，不要编造

## 二、两种 goal 模板

### 执行型模板（代码/部署/内容产物）

```markdown
## 目标
[一句话意图 + 干完什么样]

## 验收
- [命令或文件路径]：[判定标准]
- 证据：回传 [具体内容]

## 防偷懒
- [最可能的偷懒方式]：[堵死条件]
- 基线不可退：[当前基线数字]

## 边界
- 只允许改：[白名单路径]
- 预算：[时间/调用次数上限]

## 取舍
- [优先级顺序，如：正确 > 完整 > 快]

## 未知
- 摸不准的写进返回结果，跳过继续
```

**使用时直接复制** → `templates/execution-goal.md`

### 探索型模板（调研/选型/分析）

```markdown
## 目标
[要回答什么问题]

## 完成条件
- 结论 ≤ N 条，每条附来源 + 日期
- 宁收 2 条实的，不收 10 条凑的

## 证据
- 每条结论必须可复现（给 URL 或命令）
- 编造引用 = 不合格

## 预算
- 最多查 N 个来源 / N 分钟
- 烧完交"目前最优 + 还没排除什么"

## 此路不通 = 合格
- 带证据证明某方向是死路（死因 + 原始输出）
```

**使用时直接复制** → `templates/exploration-goal.md`

## 三、验收协议

delegate 结果回传后，**主 agent** 执行（不是子 agent 的活）：

### 明卷（goal 里写好的验收条件）

子 agent 返回的证据是否满足 goal 里的验收标准？逐条核对。

### 暗卷（主 agent 自留的抽查，子 agent 看不见）

- **执行型**：跑一个 goal 里没写的命令验证
  - `git diff --stat` 看实际改了哪些文件
  - `git log --oneline -3` 看有没有偷偷改
  - 重新跑一次测试看是不是稳定通过
- **探索型**：随机抽一条结论，验证来源真实性
  - curl 一下引用的 URL 看能不能打开
  - 看来源日期是不是最近的（不是 3 年前的旧数据）

### 判定

| 明卷 | 暗卷 | 结论 |
|------|------|------|
| ✓ | ✓ | 合格 |
| ✓ | ✗ | 返修（可能作弊） |
| ✗ | — | 直接返修 |

### 返修 goal 怎么写

```
验收不通过。问题：[具体哪条没过]
证据：[暗卷查到的]
重做，这次额外注意：[具体要求]
```

## 五、防作弊条款库

按场景分类，写进 goal 的「防偷懒」段。详见 `references/anti-cheat-catalog.md`。

**最常用的 5 条**：

| 偷懒方式 | 堵死条件 |
|----------|----------|
| skip 测试 / `|| true` | goal 里写明：测试必须全通过，贴最终输出 |
| mock 被测对象 | 要求贴真实 API 响应或真实文件路径 |
| 声称完成但没部署 | 要求贴可访问的 URL + curl 200 |
| 调研编造数据 | 每条结论必须附可复现的 URL 或命令 |
| 删测试降阈值 | 基线不可退：写明当前测试数/覆盖率 |
