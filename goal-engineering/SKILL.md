# Goal Engineering

> **派活前自检 + goal 模板 + 验收协议**
> 让每次 delegate_task 的输入质量稳定、验收有据可查。

---

## 什么时候用

- 你准备 delegate_task 给子 agent 之前
- 你说"帮我派活"/"帮我 delegate"
- 用户说"这个任务帮我写个 goal"
- 子 agent 返回结果后需要验收

**不做的事**：不串联流程、不替代 orchestrator、不做自动化验收、不写风格化内容。

---

## 第 1 步：七问自检

delegate 前过一遍。不是每次全填——执行型至少填 1/2/4，探索型至少填 1/2/3/7。

| # | 问题 | 判断标准 |
|---|------|----------|
| 1 | **Why** | 这个活为什么干？干完什么样？一句话能说清 |
| 2 | **Done** | 具体到什么程度算完？命令跑过？文件存在？结论条数达标？ |
| 3 | **Proof** | 谁验？怎么验？子 agent 回传什么证据？ |
| 4 | **Anti** | 最偷懒的达标方式是什么？怎么堵死？ |
| 5 | **Bounds** | 只能改哪些路径？预算多少（时间/调用次数）？ |
| 6 | **Trade** | 冲突时保哪个？（如"算得对 > 做得全 > 做得快"） |
| 7 | **Unknown** | 摸不准的怎么办？（写下来跳过，不硬闯不停） |

### 快速模式

常规低风险任务只需填 **Done + Anti** 两项。只有探索型或高风险任务才填全。

---

## 第 2 步：选模板写 goal

判断任务类型，套对应模板。模板文件在 `templates/` 目录下。

**执行型**（代码/部署/内容产物）→ `templates/execution-goal.md`

核心：验收条件必须是可执行的命令或可检查的文件路径。防偷懒条款写明基线不可退。

**探索型**（调研/选型/分析）→ `templates/exploration-goal.md`

核心：每条结论必须可复现（附 URL 或命令）。编造引用 = 不合格。此路不通 = 合格（带证据）。

---

## 第 3 步：验收协议

子 agent 返回结果后，执行验收：

### 明卷（goal 里写的验收条件）

子 agent 返回的证据是否满足？逐条对照。

### 暗卷（主 agent 自留抽查，子 agent 看不见）

- **执行型**：跑一个 goal 里没写的命令验证（如 `git diff --stat` 看改了哪些文件、`curl` 验部署的 URL）
- **探索型**：随机抽一条结论，让子 agent 在 10 分钟内复现来源

### 判定

| 明卷 | 暗卷 | 结果 |
|------|------|------|
| 过 | 过 | 合格 |
| 过 | 不过 | 返修（可能作弊） |
| 不过 | — | 直接返修 |

**暗卷只对探索型和高风险执行型执行**。常规执行型跑明卷即可。

## 做站线快速参考

| 场景 | 类型 | 关键验收 |
|------|------|----------|
| 关键词调研 | 探索型 | 结论附 SERP 证据，编造 = 失败 |
| 竞品分析 | 探索型 | 竞品数据附 URL + 日期 |
| 前端部署 | 执行型 | 部署 URL 可访问 + 移动端截图 |
| 代码重构 | 执行型 | 测试通过 + 覆盖率不降 |
| 选品/定价 | 探索型 | 定价附竞品数据 + 成本核算 |
| SEO 内容 | 执行型 | article.md 路径 + 字数在范围内 |
| 截图采集 | 执行型 | 截图路径 + macOS 窗口边框 + 来源标注 |
| BGM 选择 | 探索型 | 推荐附试听理由 + 风格匹配度 |

更多场景和防作弊条款见 `references/anti-cheat-catalog.md`。
七问填写示例见 `references/seven-questions.md`。
